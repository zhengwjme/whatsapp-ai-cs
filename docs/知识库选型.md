# 智能客服知识库选型：给 WAHA 配一个「大脑」

**前提**：WhatsApp 通道已用 WAHA 打通，`bot.mjs` 已经在调 `OPENAI_BASE_URL/chat/completions`。所以选型标准只有四条：**OpenAI 兼容接口、资源够小、中文知识库好用、能和 WAHA 共存**。

**结论**：首选 **MaxKB**（一个 docker run，官方声明兼容 OpenAI 格式，改 3 个环境变量即接入，零代码）；要 MIT 许可选 **AnythingLLM**；想要腾讯系 / Go 单体 / 自带 Agent 与 IM 渠道选 **WeKnora**（但它不是 OpenAI 兼容，需要 15 行适配）。

数据采集日：2026-09-17（GitHub API 实时取数 + 各家官方文档 / 协议原文）。

---

## 1. 接入方式：改 3 个环境变量，代码零改动

`bot.mjs` 的 `askLLM()` 走的就是 OpenAI 兼容协议，所以知识库系统只要兼容该协议，就只是换 `.env`：

```bash
OPENAI_BASE_URL=http://<kb-host>:8080/api/application/<app-id>   # 各家路径不同，见下表
OPENAI_API_KEY=<该应用里生成的 Key>
OPENAI_MODEL=<占位或真实模型名，见各家要求>
```

| 系统 | Base URL 写法 | model 字段 | 备注 |
|---|---|---|---|
| MaxKB | `http://host:8080/<应用 API 地址>` | 模型名或占位 | 应用【概览】→ API Key；官方称「兼容 OpenAI API 格式」 |
| AnythingLLM | `http://host:3001/api/v1/openai` | **workspace slug**（不是模型名） | 填模型名会返回 401/403，见 issue #2510 |
| RAGFlow | `http://host/api/v1/openai/<chat_id>/chat` | 可取 `"model"` 占位 | 旧端点 `/chats_openai/...` 已弃用 |
| FastGPT | `http://host:3000/api/v1` | FastGPT 应用模型名 | 需在应用里开 API 访问 |
| WeKnora | ✗ 不兼容 | — | 自有 REST `/api/v1`，需写适配层 |

**会话隔离怎么保证**：不要依赖知识库系统自己的会话。`bot.mjs` 已按 `chat_id` 存 SQLite 上下文并把历史整段塞进 `messages`，每个客户互不串台 —— 这也是我不建议把「多轮记忆」交给 KB 侧的原因。

## 3. 授权坑

- **MaxKB 是 GPL-3.0**：自用/自托管无所谓；把它和你的闭源代码一起对外分发就要处理 copyleft。
- **FastGPT 是 Apache-2.0 + 附加条款**：不得用其源码做同类多租户 SaaS，不得删改控制台 LOGO/版权。
- **QAnything 是 AGPL-3.0**：网络服务对外提供即触发开源义务，商业产品慎选。
- **WeKnora 是 MIT**，但第三方组件逐项声明（`THIRD_PARTY_NOTICES.md`）—— 用到 Neo4j（GPL 社区版）、Milvus 等要单独看。
- **AnythingLLM 是 MIT**，最省心。

## 4. 选型建议（按你的实际情况）

| 你的诉求 | 选 | 理由 |
|---|---|---|
| 今天就要跑通，只回答产品/FAQ 问题 | **MaxKB** | 1 条 docker run + 3 个 env，零代码。官方明说兼容 OpenAI 格式 |
| 许可要干净、以后可能商业化分发 | **AnythingLLM** | MIT，单容器；注意 `model` 填 workspace slug |
| 想要腾讯系、Go 单体、自带 Agent 和 IM 渠道 | **WeKnora Lite** | 单二进制 + SQLite，无 Redis/无向量库；但接口不兼容 OpenAI，要写适配 |
| 知识库里全是扫描件/合同/PPT | **RAGFlow** | 解析最强，代价是 16G 内存起步 |

**推荐落地顺序**：MaxKB 起一个 → 丢 10 篇产品文档 + 20 条历史 FAQ → 在 MaxKB 里建应用拿 Key → 改 `.env` 三行 → 用副号问 20 个问题，看召回和拒答率 → 不满意再换 RAGFlow。

## 5. 未验证项（我没实测，别当成结论）

- 各家 OpenAI 兼容端点在**多轮 `messages` 数组**上的真实行为（有的系统只取最后一条 + 自己的会话状态）。这是接入第一件要验的事。
- MaxKB 应用级会话与 `bot.mjs` 自带上文是否冲突（可能双份上下文）。
- 各系统与 WAHA 同机部署的实际内存占用（表里是官方文档的最低要求，不是实测值）。
- `WeKnora` 适配层我还没写，只有 API 文档层面的判断。
