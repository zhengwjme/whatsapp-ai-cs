# 管理界面跑在机器人进程内，只允许本机访问、不鉴权；`.env` 是唯一配置来源

管理员是英国的非技术人员，只有一台 Windows 机器，而机器人本身零框架、依赖只有两个。所以管理界面用 `node:http` 跑在机器人进程内，只监听 `127.0.0.1`，页面是原生 HTML/JS，`npm start` 时自动打开浏览器。只有本机能访问，所以不做登录。界面上改的配置直接写回 `.env` 中对应的 `KEY=` 行（保留注释），同时热更新内存里的 `CFG`，`.env` 始终是唯一的配置来源。

## Considered Options

- Electron / Tauri 桌面应用：要做安装包和签名，体积上百 MB，维护面比机器人本身还大。
- 单独起一个 Web 服务进程：要跨进程共享 SQLite 和 WhatsApp 连接状态，得多一套进程间通信。
- 配置存进 SQLite，覆盖 `.env` 的同名项：会出现两个配置来源，管理员分不清哪个生效。
- 开放局域网或公网访问：界面能改 `SYSTEM_PROMPT`、能看全部会话历史，必须加鉴权，现阶段不值得。

## Consequences

以后要从手机或远程访问管理界面，得先补鉴权（至少一个密码），再放开监听地址，不能只改绑定地址。
