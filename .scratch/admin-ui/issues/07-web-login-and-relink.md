# 07: 在网页上登录与重新关联

**What to build:** 管理员不用看终端就能登录 WhatsApp。需要登录时，页面显示清晰的二维码（服务端用已安装的 `qrcode-terminal` 自带的 QR 编码器生成 SVG，不加新依赖），二维码刷新后页面跟着更新；也可以选"用号码获取配对码"，在页面上填带国家码、不带 `+` 的号码，页面显示 8 位配对码，号码写回 `WHATSAPP_PHONE`。登录成功后页面自动切到已连接。页面提供"退出并重新关联"按钮，点击时用页面内的确认对话框二次确认，并说明机器人会暂时停止回复；确认后退出登录、清除登录态、重新发起连接，再次进入需要登录状态。账号在手机端被登出时，页面提示已登出，并直接给出重新关联的入口。终端里的二维码照常打印。连接适配器在本票补齐：二维码原始字符串、申请配对码、退出并重新关联；传输层要把连接事件收拢成可查询的当前状态，并把"清除登录态后重连"做成可调用的动作。

**Blocked by:** 02, 06

**Status:** ready-for-agent

- [x] 适配器处于需要登录状态时，API 返回合法的 SVG 二维码；二维码更换后返回新的
- [x] 配对码请求经过适配器，返回配对码，并把号码写回 `.env` 的 `WHATSAPP_PHONE`（注释保留）
- [x] 号码含 `+`、空格或非数字时被拒绝，适配器不被调用
- [x] 已连接时申请配对码返回明确的错误
- [x] 重新关联请求经过适配器
- [ ] 人工验收（真实 Baileys）：全新数据目录下网页扫码登录成功；配对码登录成功；二维码过期后页面自动更新；"退出并重新关联"要求确认，确认后能用另一种方式重新登录；手机端移除关联设备后页面提示已登出并能重新关联；整个过程中终端二维码依旧可用
